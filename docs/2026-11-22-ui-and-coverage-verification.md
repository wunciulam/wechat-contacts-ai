# 明亚导入、新单录入与保障字段核对

范围：添加 / 导入中的明亚页签、明亚预览和原始详情、新单录入及详情编辑。不改变其他未发布页面。

## 原因与修正

- 明亚流程曾自行定义绿色主按钮、13px控件、独立间距与手机全屏样式，没有复用 index.css。已删除 mingyaImport.css，改用 WorkspaceDialog、btn、input、table 公共模式。
- 明亚页签原来混入了表格上传及两段说明。现只保留导入采集文件入口；Excel、截图、手动录入仍各有原入口。
- 新单曾只有8个字段，且把空保费记成0、空单号写成“暂无单号”。现在新单与详情读取/编辑共用 PolicyFieldsForm 的16字段定义；未填值保持空，按投保人归属，不虚构金额和号码。
- 保障字段已经存在于原始JSON，但缺少到 coveragePeriod、expiryDate、insuranceType 的映射。现在读取主险保险期间、明确保障结束日期及主险 riskFlag；不从缴费结束日期推算保障到期，不把未知单位代码转换为猜测值。

## 文案删减（独立检查）

- 明亚页签只需导航与导入动作：删除旧表格说明、报表类型罗列及上传表格按钮。
- 上传界面只保留文件类型与选择文件操作；没有文件时不显示无法使用的合并按钮。
- 四项预览数量用于核对影响范围；“预览，尚未保存”用于区分正式数据，保留。
- 合并规则折叠展示，避免默认堆积说明。处理方式选择用于决定已有数据如何更新，保留。
- 客户冲突仅展示姓名、需要核对原因及处理选择；理由与选择用途不同，保留。
- 新单原装饰盾牌与头像、重复的归属客户/投保人选择已移除；16项业务标签各对应独立字段，按保单、缴费、保障三组排列。
- 原始详情保留“参考金额尚未形成应缴”提示，避免把参考数字误认为账单。
