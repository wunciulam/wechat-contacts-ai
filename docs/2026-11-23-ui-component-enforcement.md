# UI 一致性检查与组件约束 · 2026-11-23

## 原因与修复

1. `index.css` 的公共 `.input` 原先在 CSS layer 外。Tailwind 的 `pl-*` 等工具类在 layer 内，即使局部类看似正确，也会输给公共 padding。搜索图标绝对定位、输入框留白失效，是截图中叠字的直接原因。公共样式移回组件层；SearchInput 改为图标和输入区域的 flex 布局，不依赖局部 padding 修补。
2. 页面只有样式类约定，没有可复用的日期、下拉、表单字段实现。浏览器原生日历与站内控件混用；验收页私有下拉不参与业务。新增公共 Input/DateInput、SearchInput、Select、Field、Button/IconButton、Tag；实际业务和验收页引用同一实现，业务卡片示例直接引用 ContactCard。
3. 确认、分类、批量标签、联系人、验收弹窗分别管理外观、滚动和关闭逻辑。改为 WorkspaceDialog，正文滚动、标题/底栏固定，统一键盘关闭与焦点恢复。手机表单单列，弹出层根据可用空间调整位置，并通过 top layer 避免父容器裁切。
4. 之前以阅读规范、局部截图和构建通过代替完整回归，没有构建硬性约束。此次补上静态扫描、自检、真实浏览器关键路径、项目交付规则。不能把既有规范文件本身当成已经符合规范的证据。

## 覆盖范围和例外

从网页、组件验收、模块验收三个入口追踪本地引用；报告包含源码清单和控件用量。当前53份来源（含CSS）。业务文本、搜索、日期、下拉、按钮、标签及主要弹窗已迁移；保单详情和新单保留共用16字段。状态及历史数据逻辑沿用既有实现，不执行真实客户写入或清理。

原生 file、checkbox、radio 是明确例外。导航、Tab、拖动、颜色选择及文本/列表动作使用 Button plain；普通操作使用标准变体。表格继续复用公共表头/单元格规则及已有固定操作列，未为这次整改另造数据表框架。未引用的 ProductSpecModal、ContactDetailSidebar 是遗留源码，不作为当前页面规范或交付入口，未借本次任务重做它们；将来重新接入会进入扫描。

## 防止复发

- `npm run check:ui`：扫描入口引用图；阻止业务原生文本/日期/下拉/按钮、独立对话框、裸 Search 图标、不合规输入尺寸样式、低于12px文字、无名称图标按钮、非分层公共控件CSS。
- 检查器自检：注入故意错误的虚拟源码和CSS，确认上述规则会失败；公共原语内部和分层CSS可以通过。它不是只打印“已检查”。
- `prebuild` 自动运行静态检查，Vercel构建会受到同样约束。
- `npm run check:release`：网页类型、59项既有业务检查、静态规则、生产构建、模拟数据浏览器回归，任一失败返回非零退出。
- `.github/workflows/ui-contract.yml` 已加入仓库，设置推送/PR执行并保存截图和报告。没有声称该工作流已经在远端运行，也没有配置远端分支保护。
- AGENTS.md和design.md要求新增入口补入扫描、新交互补充回归，并检查桌面、手机、滚动、键盘、失败状态及文案。截图仍需人工走查；自动规则不代表所有浏览器、所有数据形态都不会出现视觉问题。
