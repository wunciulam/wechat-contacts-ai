# 项目界面启动模板

复制本页到新项目。只填第一部分，第二部分沿用或指出例外，第三部分交给实施者执行。

## 每个项目只填这四行

- 项目、使用者、最常用的设备或使用环境：____
- 最常做的三件事，按频率排序：____
- 视觉参照：____。老项目选一个要保留的实际页面，再选一个问题最多的流程；新项目给一个喜欢的参考，或直接写「沿用上次后台风格」。
- 本次范围、必须保留的行为和想改变的地方：____

## 可继承的偏好（按项目覆盖）

| 决策 | 当前后台项目的默认做法 |
| --- | --- |
| 信息密度 | 核心数据与操作优先。字段按用途分组，标签和值紧邻。删掉重复提示、装饰性文字和多余操作行。 |
| 色彩 | 黑白灰承载界面，五组明亮辅助色装饰分类，每组至少九档。警示要有文字，颜色从项目色板取。 |
| 文字和数字 | 标题、正文、说明各用固定层级。金额两位小数，单号保留原文，天数和期数按整数显示。 |
| 控件 | 内容 Tab 用线框表示选中，列表筛选用分段控件。功能按钮图标在文字前。多选框选中为黑底白勾。 |
| 列表和弹窗 | 同类卡片共用组件。记录操作靠右，模块设置与标题同排。弹窗固定标题、关闭和底部操作，只滚动正文。 |
| 业务状态 | 从实际业务取得状态及触发条件。例如保险项目中只有跟进中的客户显示蓝点。换项目时重新核对该项。 |

## 给实施者的启动指令

1. 老项目先盘点正在运行的页面、真实状态和共用组件，记录哪些保留、哪些冲突。新项目从最高频任务画出一个完整流程。缺少偏好时给候选默认值，仅把影响多个页面的分歧交给我选择。
2. 先制作一条可操作的代表流程。例如从客户列表打开详情、修改字段、校验并保存。用同一组组件演示长文本、空值、必填错误、禁用和手机布局。每个状态必须有真实触发场景。
3. 集中提交一次对照预览，只列需要决定的差异。收到标注后判断作用域：单页排版改当前页，组件行为改共享组件，全局规则同步写入规范。
4. 样板确认后将决定写入 design.md，把色板、字号、间距和控件尺寸落实为共用样式变量，把交互落实为公共组件。项目 AGENTS.md 指向规范与可运行样板，新页面直接复用，老页面按流程逐步替换。
5. 交付前检查桌面、手机、键盘焦点、滚动与关键操作，单独删减文案。对每处例外记录原因。新增一种交互时补相应样例，已有类型按已确认样板执行。
