# Pen 跟进流程实现

分支 codex/pen-followup-workbench；基于 d8fe13c 正式源码及 380eb35 本地OCR版本。只在本地开发，不发布、不修改线上数据库。

视觉唯一依据：Pen 的 L0ANK、gFzQc；工作台主区域 ib1WA（用户指定模板），导入 z9fzw、梗概 m64cB、详情 A32Mwt 及其最新状态副本。头像、三列卡片、灰底Tab、主副标、黑色操作、AI边框均对照画板。

实现顺序：领域与原子保存 → 按日导入审核/梗概 → 客户分析和结果录入 → 工作台和分类Tab → 失败、并发、键盘、手机、截图回归。

数据：ProgressRecord 显式 kind 区分 task 与 communication；老记录保留。任务仅用于计划与状态，沟通事实统一展示在原客户跟进历史。完成同时保存任务和结果；撤销只恢复任务，保留事实。批量保存和分析采用期望值校验，失败不显示假成功。

首页：今天及以前的未完成任务为现在要处理，明天及以后为之后有安排；未来7天先展示，更晚继续展开。已完成无常驻入口，只短暂反馈撤销。联系尝试和内部准备不更新最后有效沟通。

AI：截图本机OCR；聊天按日期/角色逐条审核，默认全选，日期未知原位核对；保存原话不保存图。每日梗概只概括客户与我的表达，和全量客户分析分开。分析使用所有已保存历史，来源可追溯，有新内容时标待更新；阶段、待办均不自动写入分类或保单。

提醒：约定优先；3/14/30天是可调整检查参数，不是自动激活规则。激活需要明确暂停原因、回访约定或新切入点；单纯长期未联系独立待检查。所有推荐关联原记录，已有对应任务不重复推荐。

本地查看：npm run dev，固定 http://127.0.0.1:4180 。进入左侧“跟进工作台”。数据空间 followup-workbench-local，使用独立 .followup-workbench-data.local，不连线上客户库；原 .chat-followup-data.local 保留。首次启动提供四位虚拟客户，内容仅用于展示。

DeepSeek 配置：把 DEEPSEEK_API_KEY 放入本机 .env.chat-local.local 并重启 dev；可选 DEEPSEEK_MODEL。线上使用相同服务端变量，不能带 VITE_ 前缀。GET /api/followup-ai 只返回是否配置，不返回 Key。当前未配置真实 Key，联调使用模拟响应；未调用真实客户材料。

上线前单独应用 supabase/migrations/20261125000100_followup_bundle.sql（本次未执行到线上）。不做此迁移时线上不会拥有新保存RPC，不应单独发布前端。迁移沿用 app_data/RLS，以 SECURITY INVOKER 执行，保留旧跟进保护触发器。此分支没有新增入口文件，新增业务路径随 App 的静态依赖扫描。

每天刷新在打开工作台时执行，仅在服务端配置AI后更新有新记录的客户。后台推送通知不在本次范围内。AI判断始终显示依据，可手动更新；提醒是候选建议，不自动联系客户。
