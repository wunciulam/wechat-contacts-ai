### 核心：电子保单直链接口（可直接 curl）

```
GET https://policy.mingya.com.cn/pms-1.0/api/policyCom/queryElectronPolicyWithWatermark?policyId=<ID>
Header: erptoken: <sessionStorage.erp_token>
→ 直接返回 PDF 字节流
```

备用域名（viewer 在非 web 域时用）：`https://nerpcs.mingya.com.cn/policy-1.0/api/policyCom/...`

**实测行为（重要）**：
- token 无效 → **HTTP 200 + content-length 0 + 空体**，不是 401。所以判断失效要看「空响应体」。
- 缺 policyId → 400 Bad Request。
- CORS 完全放开：`access-control-allow-origin` 会**回显请求 Origin**（web/d/app 三个域都验过），
  `allow-credentials: true`，`expose-headers: *`。所以在浏览器里 fetch 没问题。
- 响应头语义：`watermark-has: true` 服务端已压水印；
  `watermark-has: false` + 有 `original-url` → 该保单没有电子保单，只有保司网址（只能手动点）；
  `watermark-has: false` 且无 original-url → 返回加密 PDF，水印由前端 DOM 叠加（即下载到的文件无水印）。

### viewer 的 URL 签名规则（来自 `static/pdf/web/viewer.js`）

```js
m = MD5(token + policyId + 'MingYa2025')   // 与 location 同域时
viewer: /static/pdf/web/viewer.html?p=<policyId>&t=<token>&m=<md5>
```
`viewPolicy()` 在 `app-f4d04db13d.js` 的 `HomeIndexController` 里。
即：**已知 erp_token 就能自己造下载链接，不必走 viewer**。

### 交付的工具

`tools/mingya_policy_download.js` —— 控制台脚本，**不猜列表接口，靠挂 XHR/fetch 监听自动发现**：
1. 读 `sessionStorage.erp_token`（回退 `jettoken-pc`）
2. hook `XMLHttpRequest.prototype.open/send` 与 `window.fetch`，递归扫响应 JSON 里
   匹配 `^(policy_?id|erp_?policy_?id)$` 的字段（保单字段名是 **`policyid` 小写**）
3. 从捕获到的列表请求里识别分页参数（page/pageNum/current/currentPage…），自动翻页直到连续两页无新增
4. 3 并发调 PMS 接口下载
5. **自带最小 ZIP writer（store 模式，无压缩）打包成一个 zip** —— 规避 Chrome 多文件下载拦截

`tools/电子保单批量下载-使用说明.html` —— 内嵌脚本 + 一键复制按钮 + 4 步图文。

### 两个已踩过的坑

- **最小 ZIP 的中文文件名**：写入时必须置 UTF-8 标志位 bit 11（local header offset 6、
  central header offset 8 各 `setUint16(...,0x0800)`）。置了之后 Python zipfile / bsdtar /
  ditto 都能正确还原中文名；**只有 macOS 命令行 `unzip -l` 会显示乱码，那是 Info-ZIP 的锅，不是文件有问题**。
  已验证：`unzip -t` 全 OK。
- **ZIP 校验方法**：把脚本里 `var CRC_T = (function` 到 `/* --- 5. 主流程` 之间切片，
  `new Function(slice + 'return makeZip')()` 在 node 里直接跑，产物用 `unzip -t` 验，很快。

## v1 脚本实测失败：这个保单页没有 erp_token

用户在保单列表页跑 `mingya_policy_download.js`，控制台报：
`没找到 erp_token。请确认这是已登录的明亚页面`
→ 说明 **`sessionStorage.erp_token` / `jettoken-pc` 在这套系统里是空的**。

截图确认页面形态：顶部 nav 是「档案 / 消息 / 客户 / 保单 / 成长记录」，
保单 tab 下是「待处理 22 / 投保单 401 / 保单 32」，
卡片按钮是「电子保单 / 保全办理 / 更多」，卡片含保单号（形如 `S202503142823890805`）、
交单日期、投保人、被保人、服务人员、保额、保费。
**不是 web.mingya.com.cn 那套 Angular 页面**（那套的按钮文案完全不同）。

结论：`erp_token` 只属于 web.mingya.com.cn 的 Angular 老系统。
这个保单页是第三套系统，凭证位置未知（可能在 localStorage / cookie / 内存变量里）。
